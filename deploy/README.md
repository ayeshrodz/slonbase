# Platform templates

Ready-made setups for hosting platforms, each with slonbase and a PostgreSQL database. How to
use them is in [docs/platforms.md](../docs/platforms.md); this page is about getting them into
each platform's catalog, so they become one-click deploys.

| Platform | Files | In the catalog |
|---|---|---|
| Render | [`render.yaml`](../render.yaml), [`render/`](render) | Yes: the Deploy to Render button reads `render.yaml` from this repository |
| Fly.io | [`fly/`](fly) | No catalog: `fly launch` with these files |
| Coolify | [`coolify/`](coolify) | Not yet: [submit it](#coolify) |
| Dokploy | [`dokploy/`](dokploy) | Not yet: [submit it](#dokploy) |
| Railway | (created in Railway) | Not yet: [publish it](#railway) |

Before submitting, deploy the template once on the platform from these files, and sign in to
the dashboard through the setup link: catalogs ask for a template that works as is.

## Coolify

Coolify's one-click services are files in its repository: a Docker Compose file with a header
of comments (`documentation`, `slogan`, `tags`, `logo`, `port`), and a logo.

1. Fork [coollabsio/coolify](https://github.com/coollabsio/coolify) and create a branch from
   the branch its contributing guide names for new services.
2. Copy `coolify/slonbase.yaml` to `templates/compose/slonbase.yaml`, and `coolify/slonbase.svg`
   to `public/svgs/slonbase.svg`.
3. Follow the repository's contributing guide for anything else it asks of a new service
   (generated files are usually regenerated by the maintainers; don't edit them by hand
   unless it says so).
4. Open a pull request:

   > **Add slonbase**
   >
   > [slonbase](https://github.com/ayeshrodz/slonbase) is an open-source backend in one Rust
   > binary: collections, a REST and realtime API, auth, files, hooks and an admin dashboard,
   > with the data in PostgreSQL tables. MIT licensed.
   >
   > The template runs the official image (`ghcr.io/ayeshrodz/slonbase`) with PostgreSQL 17.
   > Coolify generates the database credentials and a setup token; after deploying, open
   > `https://<the URL>/_/setup?token=<SERVICE_PASSWORD_64_SETUP>` to create the first
   > superuser. The container has a health check (`/slonbase health`), and files, backups and
   > hooks are kept in a volume at `/data`.
   >
   > Tested on Coolify <version>.

## Dokploy

Dokploy's templates are folders in [Dokploy/templates](https://github.com/Dokploy/templates):
`docker-compose.yml`, `template.toml` and a logo, plus an entry in the catalog's index.

1. Fork the repository and create a branch.
2. Create `blueprints/slonbase/` with `dokploy/docker-compose.yml`, `dokploy/template.toml`
   and `dokploy/slonbase.svg`.
3. Add the entry in `dokploy/meta.json` to the repository's `meta.json` (in its sort order),
   and run the checks its README describes for new templates.
4. Open a pull request:

   > **Add slonbase**
   >
   > [slonbase](https://github.com/ayeshrodz/slonbase) is an open-source backend in one Rust
   > binary: collections, a REST and realtime API, auth, files, hooks and an admin dashboard,
   > with the data in PostgreSQL tables. MIT licensed.
   >
   > The template runs the official image with PostgreSQL 17, generates the database password
   > and a setup token, and routes the domain to port 8090. After deploying, open
   > `https://<domain>/_/setup?token=<SETUP_TOKEN>` to create the first superuser.
   >
   > Tested on Dokploy <version>.

## Railway

Railway templates are made from a working project, in Railway's dashboard.

1. Set up the project as in [docs/platforms.md](../docs/platforms.md#railway): PostgreSQL, the
   `ghcr.io/ayeshrodz/slonbase:latest` service with its variables (`SLONBASE_DATABASE_URL`,
   `PORT`, `RAILWAY_RUN_UID`), a volume at `/data` and a public domain on port 8090.
2. Project settings → **Create template** (or the template composer). Check that the variables
   and the volume came along, give it the name *slonbase*, the description from the Coolify
   pull request above, and the logo (`docs/assets/logo.svg`), then **Publish**.
3. Railway gives the template a deploy link, `https://railway.com/deploy/<code>`. With it, the
   Deploy on Railway button goes into the README, the project page and docs/platforms.md.
