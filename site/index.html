Why slonbase

Everything you like about PocketBase.
Your data where it belongs.

Define collections in a dashboard and get a REST API, auth, realtime and files right away, with every table a real PostgreSQL table you can query, replicate and back up.

Drop-in for PocketBase apps

The official SDKs work unchanged, and so do pb_hooks and pb_migrations. slonbase import-pocketbase brings collections, records, files, settings and even password hashes.

Real PostgreSQL tables

Each collection is a table in the slonbase schema. Query it with SQL, replicate it, pg_dump it, or run it on a managed service.

Realtime for every change

A trigger on each table announces every write, whoever makes it: the API, SQL, auth flows or another program. Subscribers see it, with their rules applied.

Scales out

Run several instances on one database behind any load balancer. Realtime, schema changes, settings and rate limits are shared through LISTEN/NOTIFY. No sticky sessions.

Every PocketBase hook

Request, model, execute, after-error, realtime, file, mail and onModel* hooks, routes, cron jobs and the $dbx query builder, in JavaScript. Or extend it in Rust.

Operations built in

Password, OAuth2, OTP and MFA sign-in; rate limits; request logs; scheduled backups to S3; Prometheus metrics; and upgrades tested from the first release.

Same code, new foundation

Keep your SDK.
Keep your hooks.

slonbase speaks PocketBase's API, filter language and hook API. A compatibility suite written with the official SDK runs against a real PocketBase and against slonbase, and must pass on both.

  • Filters and API rules, relation paths, @request.* and @collection.*
  • Auth with passwords, OAuth2 providers, one-time passwords and MFA
  • Batch requests in one transaction, expand, files and thumbnails
  • PocketBase's error messages, so your forms show the same errors
import PocketBase from "pocketbase";

// the same SDK, pointed at slonbase
const pb = new PocketBase("http://localhost:8090");

await pb.collection("users")
  .authWithPassword("ann@example.com", "secret");

const posts = await pb.collection("posts").getList(1, 20, {
  filter: 'published = true && views > 100',
  expand: "author",
});

// realtime, as before
pb.collection("posts").subscribe("*", (e) => {
  console.log(e.action, e.record.title);
});
// PocketBase hooks run as they are
onRecordCreateRequest((e) => {
  if (!e.auth) throw new ForbiddenError("Sign in first.");
  e.record.set("author", e.auth.id);
  e.next();
}, "posts");

routerAdd("GET", "/api/top", (e) => {
  const rows = arrayOf(new DynamicModel({ title: "", views: 0 }));
  $app.db().select("title", "views").from("posts")
    .where($dbx.hashExp({ published: true }))
    .orderBy("views DESC").limit(10).all(rows);
  return e.json(200, rows);
});

cronAdd("cleanup", "0 3 * * *", () => {
  $app.db().delete("posts", $dbx.hashExp({ status: "spam" })).execute();
});
-- every collection is a real table: query it, join it, index it
SELECT a.name, count(*) AS posts, sum(p.views) AS views
FROM slonbase.posts p
JOIN slonbase.users a ON a.id = p.author
WHERE p.published
GROUP BY a.name
ORDER BY views DESC;

-- and changes made here reach realtime subscribers too
UPDATE slonbase.posts SET featured = true WHERE views > 10000;

Scale out

One database.
Many servers.

Put several slonbase instances behind any load balancer. They share everything through PostgreSQL, so you scale the stateless part and keep one source of truth.

  • Realtime events reach subscribers on every instance, and subscriptions find their client's instance: no sticky sessions
  • Schema changes, settings and backup restores reload everywhere
  • Rate limits count across instances, cron jobs run once per schedule
  • Prometheus metrics on a private port: requests, latency, pool use, realtime
Honest comparison

slonbase and PocketBase.

PocketBase is a wonderful tool, and slonbase exists because of it. Here's how they differ, and when to pick which.

slonbasePocketBase
DatabasePostgreSQL 14+ (yours, or managed)SQLite, inside the process
API and SDKsPocketBase's API; the official SDKs, unchangedThe original
ExtendingPocketBase's JavaScript hooks, or RustJavaScript hooks, or Go
InstancesAny number on one database, behind any load balancerOne
Your dataReal tables: SQL, replicas, pg_dump, BI toolsA SQLite file
RealtimeEvery change, including SQL and other programsChanges made through the app
Moving partsOne binary and a PostgreSQL serverOne binary

PocketBase is the better choice when…

  • you want zero moving parts: one file, SQLite inside;
  • one small app on one small machine is the whole plan (in-process SQLite answers a single client's lookups faster);
  • you extend it in Go.

Get started

Install it your way.

slonbase connects to any PostgreSQL 14+ server. Finish with the setup wizard, or with slonbase setup.

mkdir slonbase && cd slonbase
curl -fsSLO https://raw.githubusercontent.com/ayeshrodz/slonbase/main/compose.yaml
echo "POSTGRES_PASSWORD=$(openssl rand -hex 24)" > .env
docker compose up -d
docker compose logs slonbase | grep "setup?token"
curl -fsSL https://ayeshrodz.github.io/slonbase/slonbase.gpg | sudo tee /usr/share/keyrings/slonbase.gpg > /dev/null
curl -fsSL https://ayeshrodz.github.io/slonbase/slonbase.list | sudo tee /etc/apt/sources.list.d/slonbase.list
sudo apt update && sudo apt install slonbase
sudo journalctl -u slonbase | grep "setup?token"
sudo curl -fsSL -o /etc/yum.repos.d/slonbase.repo https://ayeshrodz.github.io/slonbase/slonbase.repo
sudo dnf install slonbase
sudo journalctl -u slonbase | grep "setup?token"
curl -fsSLO https://github.com/ayeshrodz/slonbase/releases/download/v0.6.0/slonbase-0.6.0-linux-amd64.tar.gz
tar xzf slonbase-0.6.0-linux-amd64.tar.gz
./slonbase serve    # prints the setup link
# collections, records, password hashes, files and settings, from pb_data or a backup zip
slonbase setup --database-url "postgres://..." --email you@example.com --password '...'
slonbase import-pocketbase ./pb_data
cp pb_hooks/*.pb.js slonbase_hooks/   # your hooks keep working
slonbase serve

Or deploy with one click on Render, or with the setups for Fly.io and others. Packages update with apt upgrade and dnf upgrade (repository details).
